# API reference

<p class="lede">Exports of `@sigx/lynx-secure-storage` <PkgVersion npm="@sigx/lynx-secure-storage" />.</p>

The package has exactly one runtime export — `SecureStorage`, a frozen value-object (declared `as const`, not a class — never `new` it) — plus three TypeScript types. All methods run on both iOS and Android.

```tsx
import { SecureStorage } from '@sigx/lynx-secure-storage';
import type {
  SecureStorageSetOptions,
  SecureStorageGetOptions,
  SecureStorageBiometricPrompt,
} from '@sigx/lynx-secure-storage';
```

## SecureStorage

The single exported object. Its shape:

```ts
const SecureStorage: {
  setItem(key: string, value: string, opts?: SecureStorageSetOptions): Promise<void>;
  getItem(key: string, opts?: SecureStorageGetOptions): Promise<string | null>;
  removeItem(key: string): Promise<void>;
  clear(): Promise<void>;
  hasKey(key: string): Promise<boolean>;
  isAvailable(): boolean;
};
```

Encrypted at-rest key-value storage backed by the iOS Keychain and, on Android, the Keystore plus EncryptedSharedPreferences. The CRUD vocabulary (`setItem` / `getItem` / `removeItem` / `clear`) is the same as [`@sigx/lynx-storage`](/lynx/modules/storage/api/), so code can swap between the two by durability need without renaming calls. Platform: both. Every method except `isAvailable` returns a Promise and rejects on failure with a [`SigxError`](/lynx/modules/core/api#sigxerror), messages prefixed `[@sigx/lynx-secure-storage]`. Branch on its `code`: `'invalid_argument'` for a bad key or value, `'native_error'` for a failure the platform reported (raw payload on `cause`), and `'module_unavailable'` when the native module isn't linked. `hasKey` is the one exception to the argument guard — an unusable key resolves `false` instead of throwing `'invalid_argument'`.

## Methods

### SecureStorage.setItem

```ts
setItem(key: string, value: string, opts?: SecureStorageSetOptions): Promise<void>
```

Store an encrypted string, overwriting any existing value for `key`.

- **`key`** — non-empty string. Throws `'invalid_argument'` if empty or non-string.
- **`value`** — the string to encrypt. Throws `'invalid_argument'` if non-string.
- **`opts`** — optional [`SecureStorageSetOptions`](#securestoragesetoptions). With `requireBiometric: true`, every future `getItem` of this key prompts for biometrics; `setItem` itself never prompts, on either platform.
- **Returns** — `Promise<void>` that resolves on success and rejects on a native error.
- **Platform** — both.

### SecureStorage.getItem

```ts
getItem(key: string, opts?: SecureStorageGetOptions): Promise<string | null>
```

Read an encrypted string.

- **`key`** — non-empty string. Throws if empty.
- **`opts`** — optional [`SecureStorageGetOptions`](#securestoragegetoptions). Supply `biometricPrompt` when the key was stored with `requireBiometric: true`; the OS shows a prompt before returning.
- **Returns** — `Promise<string | null>`: the decrypted value, or `null` if the key is absent. Rejects with `'native_error'` on a failure such as a cancelled biometric prompt (`userCancel`) or failed authentication (`authenticationFailed`). A gated read raises the OS prompt itself — don't call `Biometric.authenticate()` before it.
- **Platform** — both.

### SecureStorage.removeItem

```ts
removeItem(key: string): Promise<void>
```

Delete a single key. A missing key is treated as success (no-op).

- **`key`** — non-empty string. Throws if empty.
- **Returns** — `Promise<void>`. Rejects only on a native error.
- **Platform** — both.

### SecureStorage.clear

```ts
clear(): Promise<void>
```

Delete every key owned by this module's service identifier. It does not touch other apps' Keychain items or other Lynx packages' preferences.

- **Returns** — `Promise<void>`. Rejects on a native error.
- **Platform** — both.

### SecureStorage.hasKey

```ts
hasKey(key: string): Promise<boolean>
```

Check whether a key is present without decrypting it — no biometric prompt — so it is safe to call on every render.

- **`key`** — string. Returns `false` for an empty key without calling native.
- **Returns** — `Promise<boolean>`: `true` if the key exists. Rejects only on infrastructure failure.
- **Platform** — both.

### SecureStorage.isAvailable

```ts
isAvailable(): boolean
```

Synchronous (non-Promise) check of whether the native module is wired into the current build. Delegates to lynx-core's module-availability check.

- **Returns** — `boolean`: `true` when the native `SecureStorage` module is registered.
- **Platform** — both.

## Types

### SecureStorageSetOptions

```ts
interface SecureStorageSetOptions {
  /**
   * When true, the OS requires biometric authentication on every
   * subsequent `getItem` of this key.
   * - iOS: stored with kSecAccessControlBiometryCurrentSet.
   * - Android: a per-key Keystore RSA pair generated with
   *   setUserAuthenticationRequired(true); the value is encrypted with a
   *   one-shot AES key wrapped by the public half, so writing never prompts.
   */
  requireBiometric?: boolean;
}
```

Options for [`setItem`](#securestoragesetitem). `requireBiometric` gates this individual key behind the OS biometric prompt on read. Adding or removing a biometric enrollment invalidates the key on both platforms, so the value must be written again. Platform: both.

### SecureStorageGetOptions

```ts
interface SecureStorageGetOptions {
  /**
   * Required when the key was stored with requireBiometric: true.
   * Android needs the strings to render BiometricPrompt; iOS uses
   * only `reason` (the prompt title is fixed).
   */
  biometricPrompt?: SecureStorageBiometricPrompt;
}
```

Options for [`getItem`](#securestoragegetitem). `biometricPrompt` supplies the strings shown on the OS prompt for biometric-gated keys. Platform: both.

### SecureStorageBiometricPrompt

```ts
interface SecureStorageBiometricPrompt {
  /** iOS: prompt text. Android: prompt subtitle. */
  reason: string;
  /** Android only — prompt title. Defaults to "Authenticate". */
  title?: string;
}
```

Strings shown on the biometric prompt. `reason` is required; if omitted or empty, both platforms default the subtitle to `"Authenticate to read secure data"`. `title` is Android-only (iOS ignores it) and defaults to `"Authenticate"`. Platform: both.
