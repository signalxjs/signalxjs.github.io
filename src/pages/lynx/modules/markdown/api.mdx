# API reference

<p class="lede">Exports of `@sigx/lynx-markdown` <PkgVersion npm="@sigx/lynx-markdown" />.</p>

The package has two entry points. The root (`@sigx/lynx-markdown`, the `"."` export) carries the renderer, the mention plugin and the richtext re-exports, with no runtime peer imports beyond `@sigx/lynx`. The `@sigx/lynx-markdown/editor` subpath adds the block-tree editor; importing it turns the optional peers (`@sigx/lynx-keyboard`, `@sigx/lynx-richtext`) into real requirements. The renderer is pure JS and renders identically on iOS, Android and Harmony — there is no native module.

The document model, formats, plugin contract and editor core are [`@sigx/richtext`](/richtext/)'s; this page documents the Lynx surface and links there for the rest.

## Components

Each component has its own page with usage, props and events — see the **[Components](/lynx/modules/markdown/components)** catalog:

- [**MarkdownView**](/lynx/modules/markdown/components/markdownview) — streaming-aware renderer (root entry).
- [**MarkdownEditor**](/lynx/modules/markdown/components/markdowneditor) — block-tree editor (`/editor` subpath).
- [**EditorToolbar**](/lynx/modules/markdown/components/editortoolbar) — formatting toolbar (`/editor` subpath).
- [**SuggestionPopup**](/lynx/modules/markdown/components/suggestionpopup) — trigger-session suggestion popup (`/editor` subpath).

## Root entry

### MarkdownViewProps

```ts
export type MarkdownViewProps =
  & Define.Prop<'value', string, false>
  & Define.Prop<'onLink', LinkHandler, false>                 // (url, node) => void — url is sanitised
  & Define.Prop<'onImageTap', (url: string) => void, false>
  & Define.Prop<'components', Partial<LynxMarkdownComponents>, false>
  & Define.Prop<'plugins', readonly RichTextPlugin[], false>;
```

`plugins` must be a stable array — changing its identity resets the incremental parse state.

### defaultComponents

The neutral, theme-agnostic Lynx component map. `MarkdownView` merges your partial `components` over it. Bullets and checkboxes are drawn as `<view>` shapes, `text` collapses soft breaks to a space, `html` shows raw HTML as literal text, and `image` renders as a tappable label.

```ts
export const defaultComponents: LynxMarkdownComponents;
```

### LynxMarkdownComponents

`@sigx/richtext`'s `ComponentMap` over Lynx elements: only `root` is required, the standard slots are typed and optional, and plugin node types are keyed by `node.type`. See [Rendering → component maps](/richtext/docs/rendering#component-maps) for every slot's props.

```ts
export type LynxMarkdownComponents = ComponentMap<JSXElement>;
export type LynxMarkdownChild = RenderChild<JSXElement>;

export interface LynxImageProps extends ImageProps {
  onImageTap?: (url: string) => void;
}
```

### createMentionPlugin

The Lynx half of the reference mention plugin: the core mention editor slice with candidate search and cleaning, the popup row renderer, `lynxMentionNode`, and `@[label](id)` through `mentionMarkdown`.

```ts
export function createMentionPlugin(options: MentionPluginOptions): LynxMentionPlugin;

export interface MentionPluginOptions {
  search(query: string): MentionCandidate[] | Promise<MentionCandidate[]>;
  renderItem?: SuggestionRenderItem;                                        // popup row
  component?: (props: MentionComponentProps) => JSXElement | string;        // preview for MarkdownView
  trigger?: string;                                                          // default '@'
  debounce?: number;
}

export interface MentionCandidate {
  id: string;
  label: string;
  kind?: string;
  [key: string]: unknown;   // display-only extras, reach renderItem only
}

export interface MentionComponentProps {
  node: Mention;
  children: LynxMarkdownChild[];
}

export interface LynxMentionPlugin extends RichTextPlugin {
  component?: (props: MentionComponentProps) => JSXElement | string;
}
```

A label cannot contain `]`, CR or LF and an id cannot contain `)`, CR or LF; candidates are cleaned, and a candidate that cleans to empty is dropped.

### lynxMentionNode

The mention node spec with the candidate's `kind` kept on the chip — a display-only field that lives in the document but never in the markdown.

```ts
export const lynxMentionNode: NodeSpec;
```

### mentionPlugin, mentionSyntax

Re-exported from `@sigx/richtext-markdown`: the read-only mention plugin (`{ name: 'mention', nodes: [mentionNode], formats: { markdown: mentionMarkdown } }`) and its `@[label](id)` inline syntax.

### Richtext re-exports

So a Lynx app keeps a single import, the root re-exports:

| Export | From | Description |
|---|---|---|
| `createTextStream` | `@sigx/richtext` | [The streaming controller](/richtext/docs/streaming#createtextstream) |
| `renderDocument` | `@sigx/richtext` | The render engine, for custom renderers |
| `markdownFormat`, `parseMarkdown`, `createIncrementalEngine` | `@sigx/richtext-markdown` | [The markdown format](/richtext/docs/markdown) |
| every type | both | `export type *` from `@sigx/richtext` and `@sigx/richtext-markdown` — `Root`, `Mention`, `RichTextPlugin`, `NodeSpec`, `ComponentMap`, `InlineSyntaxExtension`, … |

### SuggestionsApi

### Blocks, view and surfaces

| Export | Description |
|---|---|
| `BlockView` | One root block, dispatching on its schema role (`block: EditorBlock`) |
| `InlineBlock` | A text block as a `<sigx-richtext boundary-keys>` field |
| `CodeBlock` | A code block as a `<textarea>` |
