# Using Stores in Components

A store factory returns a live instance with a flat, signal-backed surface. When you read `store.x` inside a component's render function, SignalX tracks the dependency and re-renders that component whenever the value changes. This guide covers reading, async actions, sharing, lifetimes, and cleanup.

## Reading state in render

Call the factory inside a `component(...)` setup and reference the store in the returned render function. State keys and computeds read as plain values — no manual subscription is needed for rendering.

```tsx preview code live
import { component, render } from 'sigx';
import { defineStore } from '@sigx/store';

const useCounterStore = defineStore('counter', ({ defineState, defineActions }) => {
    const { state, signals } = defineState({ count: 0 });
    const actions = defineActions({
        increment() { state.count++; },
    });
    return { ...signals, ...actions };
});

const Counter = component(() => {
    const store = useCounterStore();
    return () => (
        <button class="btn btn-primary" onClick={() => store.increment()}>
            Clicked {store.count} times
        </button>
    );
});

render(<Counter />, "#sandbox");
```

## Derived values in render

Returned computeds unwrap on the instance — read them like plain (read-only) values. They update automatically as the underlying state changes.

```tsx preview code live
import { component, render, computed } from 'sigx';
import { defineStore } from '@sigx/store';

const useCartStore = defineStore('cart', ({ defineState, defineActions }) => {
    const { state, signals } = defineState({
        items: [
            { name: 'Keyboard', price: 80, qty: 1 },
            { name: 'Mouse', price: 30, qty: 1 },
        ],
    });

    const total = computed(() =>
        state.items.reduce((sum, item) => sum + item.price * item.qty, 0)
    );

    const actions = defineActions({
        addMouse() {
            const mouse = state.items.find(i => i.name === 'Mouse');
            if (mouse) mouse.qty++;
        },
    });

    return { ...signals, ...actions, total };
});

const Cart = component(() => {
    const store = useCartStore();
    return () => (
        <div class="space-y-2">
            <ul class="text-sm">
                {store.items.map(item => (
                    <li>{item.name} x{item.qty} - ${item.price * item.qty}</li>
                ))}
            </ul>
            <p class="font-bold">Total: ${store.total}</p>
            <button class="btn btn-sm" onClick={() => store.addMouse()}>Add a mouse</button>
        </div>
    );
});

render(<Cart />, "#sandbox");
```

## Async actions and `pending`

Every action carries a reactive `pending` flag — `true` while any invocation of that action is in flight. Read it in render to drive spinners and disabled states.

```tsx preview code live
import { component, render } from 'sigx';
import { defineStore } from '@sigx/store';

const useSaveStore = defineStore('saver', ({ defineState, defineActions }) => {
    const { state, signals } = defineState({ savedAt: '' });
    const actions = defineActions({
        async save() {
            await new Promise(resolve => setTimeout(resolve, 1200));
            state.savedAt = new Date().toLocaleTimeString();
        },
    });
    return { ...signals, ...actions };
});

const Saver = component(() => {
    const store = useSaveStore();
    return () => (
        <div class="flex items-center gap-3">
            <button class="btn btn-primary" onClick={() => store.save()} disabled={store.save.pending}>
                {store.save.pending ? 'Saving…' : 'Save'}
            </button>
            {store.savedAt && <span class="text-sm">last saved {store.savedAt}</span>}
        </div>
    );
});

render(<Saver />, "#sandbox");
```

Async actions return the **original promise**, so `await store.save()` observes rejections; un-awaited (fire-and-forget) calls never surface unhandled-rejection noise — failures still reach `onFailure` subscribers.

## Reacting to specific changes

To run side effects when a single key changes, subscribe to its `$events` entry. Callbacks receive `(value, prev)`; each `subscribe` returns a `Subscription` you can `unsubscribe()` later.

```tsx
const store = useCounterStore();

const sub = store.$events.count.subscribe((value, prev) => {
    document.title = `Count: ${value} (was ${prev})`;
});

// later, when you no longer need it:
sub.unsubscribe();
```

These events are lazy — the deep watcher behind a key only runs while it has subscribers, and nothing fires at subscribe time.

Subscribe to action lifecycle events the same way for cross-cutting concerns like logging or analytics — the events ride on the action function itself:

```tsx
store.save.onFailure.subscribe((error, ...args) => {
    reportError(error, args);
});
store.save.onDispatched.subscribe((result) => {
    toast('Saved!');
});
```

## Destructuring safely with storeToSignals

**Don't destructure the store directly** — `const { todos } = store` reads through the unwrap proxy and snapshots the current value, losing reactivity. When you want destructured locals, use `storeToSignals`, which returns signal views (`{ value }`) for every state key and computed:

```tsx
import { storeToSignals } from '@sigx/store';

const store = useTodoStore();
const { todos, remaining } = storeToSignals(store);

todos.value.push({ id: 1, text: 'hi', done: false }); // still reactive
remaining.value;                                       // read-only computed view
```

Actions don't need this — they are plain functions and can be referenced freely (`const { add } = store` is fine for an action, though calling through the store keeps things uniform).

## Sharing one instance vs. fresh instances

The third argument to `defineStore` is the instance **lifetime** — a string literal, defaulting to `'scoped'`:

```ts
import { defineStore } from '@sigx/store';

const useAppStore = defineStore('app', setup, 'singleton');
```

- `'singleton'` — one shared instance per app (`AppContext`), created on first use and disposed on `app.unmount()`. Outside any app context, one instance per JS realm. Ideal for global app state.
- `'scoped'` (default) — the nearest instance provided via `defineProvide` in the component tree; falls back to the app-context instance when no provider exists.
- `'transient'` — a new instance every time the factory is called, auto-disposed with the calling component.

Pick `'singleton'` when several components must read and write the same state. Pick `'transient'` when each component should own an isolated copy.

## Parameterized stores

A setup can accept any number of extra parameters after the context — they are tuple-typed with full inference (no fixed arity ceiling). Those parameters are forwarded through the factory call, letting you seed a store per instance.

```tsx
import { defineStore } from '@sigx/store';

const useListStore = defineStore('list', ({ defineState }, initialItems: string[]) => {
    const { signals } = defineState({ items: initialItems });
    return { ...signals };
}, 'transient');

// create instances seeded with different data
const left = useListStore(['a', 'b']);
const right = useListStore(['x', 'y', 'z']);
```

> For non-`'transient'` lifetimes, arguments are honored at **first creation only** — later calls resolve the existing shared instance.

## Cleanup and lifetime

When you create a store instance **inside a component**, it is tied to that component's lifecycle (per the lifetime rules above). On unmount the instance disposes: its state watchers stop and all event topics are destroyed, so `$events` and action events stop firing.

If you create an instance **outside** a component, dispose it yourself when you are done:

```ts
const store = useCounterStore();
store.count = 1;   // subscribers fire

store.$dispose();  // stop watchers + destroy topics
store.count = 2;   // subscribers no longer fire
```

Each instance has a friendly id, `store.$id` (e.g. `'counter#1'`) — handy in logs and devtools.
