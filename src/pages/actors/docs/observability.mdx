# Observability

<p class="lede">[`@sigx/actors-otel`](/actors/packages/actors-otel/overview) turns the host's
own metrics into something your monitoring stack already speaks — without making OpenTelemetry
a dependency of anything that does not want it.</p>

```bash
pnpm add @sigx/actors-otel
```

## Prometheus

The `/prometheus` entry imports **no OpenTelemetry at all**:

```ts
import { prometheusOps } from '@sigx/actors-otel/prometheus';

app.use(metrics()).use(prometheusOps({ secret: process.env.SIGX_OPS_SECRET }));
```

Mounts `GET /_sigx/metrics` beside [`ops()`](/actors/docs/ops-endpoint), with the same bearer
posture — **the secret is mandatory outside dev**.

```yaml
scrape_configs:
  - job_name: sigx-actors
    metrics_path: /_sigx/metrics
    authorization: { credentials_file: /etc/prometheus/sigx-ops-secret }
    static_configs: [{ targets: ['actors-host:7311'] }]
```

Options: `path` (default `/_sigx/metrics`), `secret`, `prefix` (default `sigx_actors_`),
`bucketsSeconds` — a per-octave grid from 1µs to ~134s, about 28 bounds — and `cluster`, for
[dispatch locality](#cluster-dispatch-locality).

`renderPrometheus(digest, stats, options)` is the pure function underneath, if you would
rather serve it yourself. Among what it emits is `{prefix}one_way_failures_total` — a
[one-way call](/actors/docs/one-way-calls) that failed *after* acceptance has nowhere else to
be reported, so this counter is the only place it surfaces in Prometheus.

> **The cardinality rule: labels are `type` and `method` — never actor keys.** An actor key is
> unbounded by construction, and a key-labelled metric will take your Prometheus down. This is
> enforced, not advisory.

> **`metrics().reset()` breaks monotonicity.** Prometheus counters are expected only ever to
> increase; a `reset()` looks like a counter restart. That is survivable — `rate()` handles
> restarts — but do not wire `reset()` to anything periodic.

## OpenTelemetry traces

```ts
import { otelTraces } from '@sigx/actors-otel';

app.use(otelTraces({ turnSpans: true }));
```

One **CLIENT** span per dispatch and one **SERVER** span per turn, joined across hosts by the
W3C `traceparent` the runtime propagates: captured from the public endpoint header and carried
on the cluster envelope.

Span attributes use a **key hash**, not the key, for the same reason the
[routing token](/actors/docs/locality-routing) does — and with the same caveat that a hash is
log hygiene, not privacy.

`@opentelemetry/api` is an **optional** peer dependency. With no tracer provider registered
the plugin is inert and costs nothing.

## The metrics bridge

```ts
import { otelMetricsBridge } from '@sigx/actors-otel';

app.use(otelMetricsBridge({ percentileGauges: true }));
```

Feeds the host's counters and histograms into whatever OTel meter provider you have
configured, for stacks that collect metrics over OTLP rather than by scraping — including
`sigx.actors.calls.one_way_failures`, the OTLP spelling of the counter above.

## Socket sessions

[Socket connections](/actors/docs/socket-sessions) are counted separately, because none of the
things worth watching about them — how many are open, how long they live, how many were
refused — are visible to the turn metrics.

`socketStats()` is one recorder per host or listener, handed to every session:

```ts
import { socketStats } from '@sigx/actors/server';

const stats = socketStats();
attachActorSocket(server, { host, stats });
```

Publish it as an ops section, and it appears under `ops.sockets` behind the existing
[bearer posture](/actors/docs/ops-endpoint) — no endpoint changes:

```ts
registry.reportOps('sockets', () => stats.snapshot());
```

`snapshot()` carries the totals — connections opened, closed and **refused** (origin or auth,
turned away before serving a byte); calls started and failed; subscriptions opened and closed,
and `subscriptionsShed` — those closed by the [slow-consumer cap](/actors/docs/socket-sessions#shedding-a-slow-consumer), also counted in
`subscriptionsClosed`;
`protocolBreaches` (1003/1009) and `lifetimeCloses` (1008 from `revalidateMs` or
`maxConnectionMs`) — plus three live gauges summed across open sessions (`open`, `inFlight`,
`subscriptions`) and a connection-lifetime histogram, `null` until there is data.

Four more fields describe live delivery:

| Field | What it counts |
|---|---|
| `deliveries` | `{i,v}` frames pushed for a live **subscription** — not call results, not stream chunks |
| `deliveryBytes` | outbound bytes for those frames, as UTF-16 code units — exact for ASCII, under-reports otherwise, deliberately: no UTF-8 pass on the hot path |
| `throttleQuantized` | subscriptions whose requested [`throttleMs`](/actors/docs/live-reads#ask-for-a-slower-delivery-window) the server's policy rounded |
| `bufferedBytes` | the **host's** own send-buffer depth, summed across open sessions — `number \| null` |

**`deliveries` is the number to watch.** A delivery is ~77% socket write, one write syscall
per subscriber, so it is what a fan-out host's cost is proportional to. Pair it with `open`
and `subscriptions`: the same subscription count on fewer connections measured 6–10× cheaper
per delivery, so **subscriptions per connection** is a ratio worth showing.

<div class="alert alert-warning not-prose my-4">
  <div>
    <strong><code>bufferedBytes: null</code> is not zero.</strong> It means no open session
    could report one — a custom adapter that does not supply the seam, or no open sessions at
    all. Reporting it as 0 would say "the hosts are not buffering", which is a claim nobody has
    measured. Same rule <code>lifetimeMs</code> follows.
  </div>
</div>

It is a gauge, and it is polled: a burst between two scrapes is invisible, so it under-reports
peaks the way `open` does. The Node adapter supplies it automatically from the socket's
`bufferedAmount`; a custom adapter passes `bufferedBytes()` to
[`createActorSocketSession`](/actors/docs/socket-sessions) if its transport can report a queue
depth, or accepts that the host cannot report its own backpressure.

`stats.digest()` is the mergeable form, in the same log-linear layout as every other
histogram, so a fleet-wide view merges the way [cluster stats](/actors/docs/cluster-stats)
does.

### Wiring the exporters and the dashboards

Two registrations, one per consumer — **this is the one step the app has to do**:

```ts
registry.reportOps('sockets', () => stats.snapshot());   // ops → the monitor, CLI and dashboard
registry.reportDigest('sockets', () => stats.digest());  // → prometheusOps and otelMetricsBridge
```

With the digest registered, `prometheusOps()` emits the `{prefix}socket_*` families:

| Family | Type |
|---|---|
| `socket_connections_opened_total` / `_closed_total` / `_refused_total` | counter |
| `socket_calls_total` / `socket_calls_failed_total` | counter |
| `socket_subscriptions_opened_total` / `_closed_total` | counter |
| `socket_protocol_breaches_total`, `socket_lifetime_closes_total` | counter |
| `socket_deliveries_total`, `socket_delivery_bytes_total`, `socket_throttle_quantized_total` | counter |
| `socket_sessions`, `socket_subscriptions` | gauge — opened − closed |
| `socket_connection_duration_seconds` | histogram, on the same bucket grid as the call histograms |

`socket_delivery_bytes_total` is in UTF-16 code units, like `deliveryBytes` above.

**No digest, no family.** A host that registers none emits no `socket_*` family at all — "no
socket mount" is not "zero connections", and a scraper that sees the family appear knows the
transport is mounted. `renderPrometheus()` takes the digest as `options.sockets`
(`SocketStatsDigest`, exported).

`otelMetricsBridge()` observes the same set as `sigx.actors.socket.*` instruments, plus
`sigx.actors.socket.connection_duration.p50` / `.p90` / `.p99` under `percentileGauges`.

On the ops side, the monitor, the [CLI](/actors/packages/actors-cli/installation#what-the-screens-show)
and the [dashboard](/actors/packages/actors-dashboard/overview) render the section for the
**polled** host only — the cluster fan-out carries no socket digest, so every other host's
socket figures read as "said nothing".

## Cluster dispatch locality

Hand the exporters this host's cluster counters and they publish the per-request
[locality](/actors/docs/locality-routing#measuring-it) pair:

```ts
const clustered = cluster({ providers, advertise, secret: process.env.HOST_SECRET });

app.use(clustered)
   .use(metrics())
   .use(prometheusOps({
       secret: process.env.SIGX_OPS_SECRET,
       cluster: () => clustered.placement.counters(),
   }));
```

`cluster` is a thunk read on every scrape or collection, so it may answer `undefined` until
placement is up. It adds:

| Exporter | Emits |
|---|---|
| `prometheusOps({ cluster })` | `{prefix}cluster_dispatches_total`, a counter with two series: `locality="local"` and `locality="remote"` |
| `otelMetricsBridge({ cluster })` | `sigx.actors.cluster.dispatches`, the same pair under a `locality` attribute |

There is no precomputed ratio gauge. The fleet-wide local-hit fraction is a query — add
`by (instance)` to both sums for the per-host one:

```promql
sum(rate(sigx_actors_cluster_dispatches_total{locality="local"}[5m]))
  / sum(rate(sigx_actors_cluster_dispatches_total[5m]))
```

**Without the option, or while the thunk answers `undefined`, no cluster family is emitted** —
a single host is not a cluster with zero dispatches. `renderPrometheus()` takes the totals as
`options.cluster`.

## Choosing

| You have | Use |
|---|---|
| Prometheus / VictoriaMetrics / Grafana Agent | `prometheusOps()` — no OTel dependency |
| An OTLP collector | `otelMetricsBridge()` + `otelTraces()` |
| Neither, and a terminal | the [CLI dashboard](/actors/packages/actors-cli/overview) |
| A custom stack | read [`ops()`](/actors/docs/ops-endpoint) directly |

Core plumbing this rides on: `ActorCallContext.traceparent`, the trailing `call` parameter on
`ActorTurnObserver`, and `bucketUpperBoundsUs()` / `timingSafeEquals` from
`@sigx/actors/host`.
